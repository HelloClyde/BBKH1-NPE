# 行走动画与计时修复

v0.1.8 同步上游 v0.1.4，修正每姿态固定67毫秒及先提交后等待的行为。

直接重新解码原 `NP560.PRG`（SHA256 `d555609e03ece17f42c1881beeb88361572f18621161de67bc9dc765857089f5`）：历史源地址46:BDD8传10，BDDC调用03:411C等待，BDE2调用03:422C提交。等待参数为毫秒，经4E:7286换算为 `max(1, floor(ms*64/1000))`，写软件计数器0494。固件TBC配置8009对应64Hz，中断对非零计数减1，前台检测到期生成4/F0事件。

新的上游代码使用SDL游戏时钟的公共64Hz相位，参数10等待下一个tick边界，结束后再提交。毫秒截止时间向上取整；暂停时游戏时钟冻结，因此继续游戏后仍能完成等待。H1的80Hz粗时钟、绘图和音频工作可能使提交晚于截止时间，不声称真机恒定15.625毫秒帧率。

成功行走仍在原位置播放0、1、2、0四姿态，然后更新一格坐标或滚动16像素地图。受阻时可能只有姿态而无位移，保持原版表现。没有加入连续平移插值，存档格式不变。

验证包括：上游无资源SDL计时测试和42次原版行走画面对照；H1正式MIPS回调在80Hz模拟时钟下检查等待前屏幕不变、等待后提交、退出中断和零等待；24次MIPS行走提交与原参考逐像素一致，覆盖左右滚屏、上下移动和地形受阻。完整H1 V1.41固件模拟器验证正式BDA的实体/触摸方向、暂停、音量、关于及退出。具体身份与边界见 `docs/evidence/walk-v0.1.8-verification.json`。
